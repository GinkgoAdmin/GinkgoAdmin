# 日志审计

## 1. 功能定位
日志审计用于记录系统操作、个人操作历史和请求行为，是问题排查、审计追踪和趋势分析的重要基础。

## 2. 核心能力
- 提供操作日志列表与「我的日志」接口。
- Web 后台提供日志查看页。
- 仪表盘还能消费日志趋势接口形成总览。

## 3. 使用场景
- 排查某个用户做过什么操作。
- 审计后台高风险行为。
- 从仪表盘观察近期日志趋势。

## 4. 使用方法
- 管理员进入日志管理页按模块、功能、类型和关键字筛选。
- 普通用户查看「我的日志」了解自身操作历史。
- 需要看详情时进入日志详情面板。

## 5. 快速调用
- `GET /api/v1/logs`
- `GET /api/v1/logs/my`
- 仪表盘趋势：`GET /api/v1/dashboard/log-trend`

## 6. 二次开发
- 新增系统能力时应考虑是否需要进入操作日志。
- 审计扩展优先沿用主框架日志体系，不要各模块各自落一套审计表。

## 7. 关键入口
- 服务端：`src/Server/Ginkgo.Api/Controllers/LogsController.cs`
- Web：`web/src/views/admin/system/Logs.vue`
- Web API：`web/src/api/system.ts` 中的日志请求封装

## 8. 注意事项
- 日志展示应注意敏感字段脱敏。
- 排查问题时要区分系统日志、我的日志和仪表盘趋势三个入口。

## 9. 常见问题
- 日志页为空：先检查筛选条件与接口返回。
- 只在首页看趋势不够：深入排查时应进入日志列表和详情。
