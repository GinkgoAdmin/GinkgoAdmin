# 前台用户与门户鉴权

## 1. 功能定位
前台用户与门户鉴权用于区分后台管理端与 Web 前台门户端的登录态、用户资料和令牌持久化，是双 Web 入口共用同一后端时的关键隔离层。

## 2. 核心能力
- Web 前台门户使用独立的 `web_user_token` 与 `web_user_info` 存储键，与后台 `auth-token` 互不串用。
- `web/src/api/http.ts` 会按路径判断当前请求属于后台还是门户，并自动切换令牌来源。
- `WebUserController` 提供门户用户中心相关接口。
- 门户认证状态由 `webAuth` Store 统一维护。

## 3. 使用场景
- 后台管理端与门户端共存且不希望登录态串用。
- 门户用户访问 `/web/*` 页面、登录、维护个人资料、查看个人通知/消息。
- 门户页需要读取当前门户用户资料并保持独立会话。

## 4. 使用方法
- 门户登录后调用 `useWebAuthStore().login(...)` 保存令牌和用户信息。
- 门户页面请求统一走 `web/src/api/http.ts`，由路径自动识别门户模式。
- 需要读取用户中心信息时调用门户用户中心一类接口。

## 5. 快速调用
- 门户首页：`web/src/views/web/index`
- 门户登录：`web/src/views/web/login`
- 门户用户中心：`web/src/views/web/user/UserCenter.vue` 等
- 门户状态：`web/src/stores/webAuth.ts`
- 统一请求：`web/src/api/http.ts`
- 服务端入口：`src/Server/Ginkgo.Api/Controllers/WebUserController.cs`

## 6. 二次开发
- 新门户页面必须继续复用 `webAuth` Store 和统一 `http` 实例。
- 门户能力扩展应尽量挂在门户控制器与门户视图目录（`web/src/views/web`）下，不要混入后台管理员链路。
- 会员中心容器路由（`/web/user*`）已在 `meta` 中标记 `portalShellNeedsPlugins: true`，由 `router/index.ts` 的 `ensurePortalPluginsLoaded()` 触发首次门户全量插件装载，使 `portal:user-menu` 等门户共享插槽钩子在静态路由命中时也能正确收集；详见 [插件开发规范与流程](./插件开发规范与流程.md) 第 9.6 节。

## 7. 关键入口
- 服务端：`src/Server/Ginkgo.Api/Controllers/WebUserController.cs`
- Web Store：`web/src/stores/webAuth.ts`
- HTTP 分流：`web/src/api/http.ts`
- 前台首页：`web/src/views/web/index`
- 门户路由：`web/src/router/web.ts`

## 8. 注意事项
- 后台与门户只是前端入口不同，底层仍共享同一服务端和主框架能力。
- 门户路径识别依赖 URL 规则，改路由时要同步检查令牌切换逻辑。
- 门户登录页 `/web/login` 是静态注册路由，登录态钩子（如 `slot:login-actions`、`http:biz-error`、`portal:standalone-route`）必须由对应插件在 `module.json` 中声明 `"loadPolicy": "always"` 才会装载。

## 9. 常见问题
- 门户登录后后台也被顶掉：通常是错误地把令牌写到了后台存储键。
- 门户接口 401：先检查路径是否被识别为门户路径，再看 `webAuth` 是否初始化成功。
- 进入会员中心看不到插件菜单项：检查会员中心容器路由 `meta` 是否带 `portalShellNeedsPlugins: true`。
