# 文档总索引

## 1. 概述

本目录用于说明 Ginkgo 主框架（开源版）的核心能力体系，覆盖服务端与 Web 宿主（后台 + 前台门户）两部分。本目录只描述当前仓库中真实存在的主框架能力，不展开各业务模块/插件内部的业务规则与页面细节。

## 2. 阅读顺序

1. 先读 [主框架总览](./主框架总览.md)、[安装与部署](./安装与部署.md)、[架构与运行机制](./架构与运行机制.md)。
2. 再读 [认证与登录](./认证与登录.md)、[权限管理](./权限管理.md)、[模块加载与热插拔](./模块加载与热插拔.md)、[插件注入与加载机制](./插件注入与加载机制.md)。
3. 日常使用时按具体功能查阅对应分册。
4. 需要做服务端模块或 Web 插件的二次开发时，阅读 [插件开发规范与流程](./插件开发规范与流程.md)、[统一设计调用规范](./统一设计调用规范.md) 与 [Web宿主附录](./Web宿主附录.md)。

## 5. Web 宿主形态

- **后台管理端**：`/admin/*`，承担用户、角色、菜单、模块、设置等系统管理能力。
- **前台门户**：`/web/*`，前台首页位于 `web/src/views/web/index`，承担门户用户登录、用户中心、消息中心等公开/半公开访问场景；前后台通过 `web/src/api/http.ts` 自动按路径切换 `auth-token` 与 `web_user_token`。

## 6. 编写约定

- 文件名统一使用中文功能名，便于直接按业务词搜索。
- H1 统一使用文档名，功能类分册统一采用 `功能定位 / 核心能力 / 使用场景 / 使用方法 / 快速调用 / 二次开发 / 关键入口 / 注意事项 / 常见问题` 九段结构。
- 机制文档额外提供 Mermaid 图，并在文中标明关键源码入口。
- 所有说明以当前仓库代码、配置和目录结构为准，不把历史旧文档视为当前实现。

## 7. 使用建议

- 查系统整体能力时优先看总览类文档。
- 查某个后台页面或 API 时优先看对应功能分册。
- 查链路、源码入口、加载过程时优先看机制类文档。
- 做服务端模块或 Web 插件二开时，结合 [插件开发规范与流程](./插件开发规范与流程.md)、[统一设计调用规范](./统一设计调用规范.md) 与 [Web宿主附录](./Web宿主附录.md) 一起看。

## 8. 维护说明

- 新增主框架能力时，应同步在本索引补目录、补矩阵、补阅读顺序。
- 业务模块/插件自身文档不应混入本目录，应保持在模块或插件自身目录中。
- 本目录是开源版主框架文档基线，不含具体业务模块/插件的功能说明。
