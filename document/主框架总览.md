# 主框架总览

## 1. 概述
Ginkgo 主框架（开源版）是一个围绕 `.NET 8 + ASP.NET Core + Vue 3` 组织起来的服务端 + Web 宿主底座。当前仓库中，主框架负责启动装配、认证鉴权、权限链路、系统设置、文件存储、消息通知、实时通信、模块装载、插件宿主和后台/前台公共能力。

## 2. 背景与目标
- 让基础能力沉淀在主框架中，避免每个业务模块重复建设用户、角色、菜单、日志、文件、通知和系统配置。
- 通过服务端模块机制（`IServerModule`）和 Web 插件机制（`web/src/plugins/core`），实现主框架稳定、业务扩展独立。
- 让 Web 后台与 Web 前台门户共享同一套身份、权限、接口和资源访问方式，降低维护成本。
- 保持主框架与业务模块/插件的边界清晰，避免业务需求反向污染底座。

## 3. 总体架构
- **服务端**位于 `src/Server`，以 `Ginkgo.Api` 为入口，分为 `Application`、`Domain`、`Infrastructure`、`Persistence`、`Realtime`、`Plugin.Abstractions`、`Shared` 等部分。
- **Web 宿主**位于 `web/src`，包含两个形态：
  - **后台管理端**（`/admin/*`，主要视图在 `web/src/views/admin`）：承载用户、角色、菜单、模块、设置等系统管理能力。
  - **前台门户**（`/web/*`，前台首页在 `web/src/views/web/index`，门户用户中心在 `web/src/views/web/user`）：承载门户登录、用户中心、消息查看等场景。
- 后台与门户共享同一服务端，通过 `web/src/api/http.ts` 按路径自动切换后台 `auth-token` 与门户 `web_user_token`。

## 4. 运行机制
- 启动入口是 `src/Server/Ginkgo.Api/Program.cs`，通过 `Bootstrap` 扩展方法完成配置、数据库、鉴权、实时通信、应用服务和模块预加载。
- 安装模式由 `InstallerService` 与资源目录下的锁文件决定，首次安装会进入安装管道，写入 `resource/db.json` 与 `resource/install.lock`。
- 正常模式下，服务端先注册控制器、鉴权、模块与静态资源，再映射 API、Hub、安装端点和 SPA 回退路由。
- 服务端模块通过 `IServerModule` 注入运行时；Web 插件通过 `web/src/plugins/core` 注入到 Web 宿主。

## 5. 安装与部署
- 默认数据库环境是 MySQL；同时内置 **SQL Server 2016+** 与 **PostgreSQL 14+** 方言支持（安装向导自动列出可用方言）。
- 服务端可独立运行并托管 Web 构建产物（后台 + 前台门户）。
- Web 后台与前台门户可独立开发构建，生产环境通常以构建产物方式由服务端托管。
- **数据库方言**通过 `IDatabaseDialect` 抽象屏蔽方言差异，主框架核心代码不出现任何 `IsMySql` 二元 if 与方言专属字面量。新增 Oracle / 达梦 / 人大金仓等数据库的标准流程详见《[数据库方言扩展规范](./数据库方言扩展规范.md)》。

## 6. 使用方式
- 后台日常使用主要通过 Web 管理端的系统管理页面完成，包括用户、角色、部门、菜单、字典、配置、文件、日志、通知、模块和插件管理。
- 前台门户用户使用 `/web/login` 等门户路由登录，访问 `/web/user/*` 维护个人资料和查看个人通知/消息；登录态写入 `web_user_token`，与后台 `auth-token` 隔离。
- 系统集成优先通过公开 API、统一 HTTP 封装、统一文件访问方式和统一权限模型接入。

## 7. 二开入口
- 服务端二开入口主要在 `src/Server/Ginkgo.Api`、`src/Server/Ginkgo.Plugin.Abstractions` 与 `src/Server/Ginkgo.Realtime`。
- Web 宿主二开入口主要在 `web/src/api`、`web/src/stores`、`web/src/plugins/core`、`web/src/views/admin/system`、`web/src/views/web`。

## 8. 注意事项
- 前端传递雪花 ID 时应保持字符串，不要把长整型主键转换成 JS `Number`。
- 主框架默认使用本地时间链路（`DateTime.Now`），新增代码时不要擅自改为 UTC 流程。
- 业务模块或插件不得为单个业务需求修改主框架核心边界，应优先走契约项目（`Ginkgo.Module.XXX.Contracts`）和插件扩展点。
- 后台与门户共享同一后端，但路径前缀与令牌存储不同，新增前端代码时要确认调用归属。
