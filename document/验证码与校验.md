# 验证码与校验

## 1. 功能定位
验证码与校验负责短信、邮箱或其他校验渠道的验证码发送、校验、渠道查询和模板管理，是认证、安全和通知链路的通用基础能力。

## 2. 核心能力
- 提供验证码发送、校验、渠道查询接口。
- 提供验证码模板列表、保存和删除接口。
- Web 端有统一验证码 API 封装，可用于注册、找回密码和高风险操作校验。

## 3. 使用场景
- 用户注册、找回密码和联系方式验证。
- 敏感操作前的二次确认。
- 管理员维护验证码模板。

## 4. 使用方法
- 业务侧先调用发送接口，再提交验证码到校验接口。
- 模板管理页或后台逻辑可维护不同用途、不同渠道的模板。
- 前端可先查询可用渠道，再动态决定采用哪种方式发送。

## 5. 快速调用
- `POST /api/auth/verification/send`
- `POST /api/auth/verification/validate`
- `GET /api/auth/verification/channels`
- `GET /api/auth/verification/templates`
- `POST /api/auth/verification/templates`

## 6. 二次开发
- 新的验证码场景优先复用现有用途、渠道和模板体系。
- 高风险操作若需人工审批或复核，应与现有验证链路配合，而不是直接绕开。

## 7. 关键入口
- 服务端：`src/Server/Ginkgo.Api/Controllers/VerificationController.cs`
- Web API：`web/src/api/auth.ts` 中的验证码相关方法

## 8. 注意事项
- 验证码是通用能力，不应在每个模块里重复维护独立发送和校验逻辑。
- 模板变更会影响多个入口，修改前要确认用途和渠道映射。

## 9. 常见问题
- 发送成功但无法校验：先检查用途值、目标值和是否已被消费。
- 页面拿不到渠道列表：检查渠道配置与接口返回。
