# 安装与部署

## 1. 概述
本篇说明开源版主框架的安装模式、环境要求、初始化方式、常用启动命令和 Web 宿主部署关系，重点覆盖服务端安装器、数据库初始化、Web 后台与前台门户的构建与托管。

## 2. 背景与目标
- 把首次安装、数据库接入和管理员初始化统一收口到安装器中，减少人工改库与手工造数。
- 明确服务端、Web 后台、Web 前台门户的启动边界，避免把开发命令、构建命令和生产部署混为一体。
- 保证默认 MySQL 环境下可以快速落地。

## 3. 总体架构
- 服务端入口是 `src/Server/Ginkgo.Api/Ginkgo.Api.csproj`，负责 API、安装页、Swagger、静态资源和模块装载。
- 安装器核心在 `src/Server/Ginkgo.Api/Install/InstallerService.cs`，安装页模板在 `src/Server/Ginkgo.Api/Install/install.html`。
- 首次安装使用 `resource/mysql_install.sql`；如需手工初始化可参考 `resource/mysql_init_menus.sql` 等脚本。
- Web 构建产物（后台 + 前台门户）由服务端通过 SPA 静态文件托管。

## 4. 运行机制
- `Program.cs` 启动时会先加载 `json/jsonc` 配置、数据库配置和 Kestrel URL。
- 当系统尚未安装时，会进入安装模式，仅保留最小中间件、Swagger 与安装端点。
- 安装成功后，安装器写入 `resource/install.lock` 与 `resource/db.json`，后续重启进入正常模式。
- 正常模式会继续装配鉴权、应用服务、文件存储、模块预加载、控制器映射和前端静态资源托管。

## 5. 安装与部署
- 基础环境建议准备 `.NET 8 SDK`、Node.js（18+）、MySQL 5.7+ 或 8.0。
- 服务端启动命令：`dotnet run --project src/Server/Ginkgo.Api/Ginkgo.Api.csproj`，默认监听 `http://localhost:5288`。
- 首次启动未检测到 `resource/install.lock` 时进入安装模式，浏览器访问 `http://localhost:5288/install` 完成数据库连接、管理员账号与站点信息设置。
- 安装完成后建议**重启后端服务**，让安装锁与数据库配置生效。
- Web 前端通常在 `web` 目录下安装依赖并运行 `npm run dev`（开发态）或 `npm run build`（生产态）；生产产物由服务端静态托管。
- 安装向导会随机生成一段后台路径前缀，请在安装完成页复制并保存，按 `<前缀>/` 进入后台。

## 6. 使用方式
- 首次运行时先访问安装页完成数据库连接、站点信息和管理员账号设置。
- 安装完成后用管理员账号进入后台，优先检查系统设置、文件存储、权限菜单和模块状态。
- 构建部署时应确认 Web 静态资源和 `resource` 目录都进入目标环境。

## 7. 二开入口
- 安装流程改造入口在 `InstallerService.cs`、`InstallModels.cs` 与 `InstallEndpoints.cs`。
- 数据库初始化脚本的手工维护入口在 `resource/*.sql`。
- 部署行为相关的启动扩展入口在 `Bootstrap/StaticFiles.cs`、`Bootstrap/EndpointMapping.cs` 与 `Program.cs`。

## 8. 注意事项
- 默认数据库应按 MySQL 处理，除非明确确认当前实例实际使用的是其他库。
- 安装器生成的 `db.json` 与 `install.lock` 直接影响系统是否进入安装模式，不应随意删除或伪造。
- Web 端 HTTP 实例已内置 `/api` 前缀，新增前端代码不要重复拼接 `/api`。
- Web 后台与前台门户共享同一服务端，部署时只需托管同一份 `web/dist` 产物，路径前缀（`/admin`、`/web`）由前端路由内部处理。
