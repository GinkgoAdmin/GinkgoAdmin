# 文件存储

## 1. 功能定位
文件存储负责上传、查询、预览、下载、删除、批量移动和代理访问，是主框架统一的资源入口。

## 2. 核心能力
- 提供文件列表、详情、上传、内容预览、下载、删除和代理访问接口。
- 支持批量移动和批量删除。
- Web 后台提供系统级文件管理页。

## 3. 使用场景
- 上传头像、LOGO、通知附件、配置图片和通用业务附件。
- 后台统一管理资源文件。
- 前端根据资源路径解析出可访问 URL。

## 4. 使用方法
- 在系统文件页上传或检索文件。
- 预览时走内容接口，下载时走下载接口。
- 文件型配置或通知附件都应尽量复用统一文件能力。

## 5. 快速调用
- `GET /api/v1/files`
- `POST /api/v1/files/upload`
- `GET /api/v1/files/{id}/content`
- `GET /api/v1/files/{id}/download`
- `POST /api/v1/files/batch-move`

## 6. 二次开发
- 新模块涉及附件时优先复用统一文件接口和文件 URL 解析能力（`web/src/utils/resourceUrl.ts`）。
- 资源 URL 处理统一走 `resolveResourcePath` / `resolveFileUrl`，不要在业务里手写 `/uploads/` 路径拼接。

## 7. 关键入口
- 服务端：`src/Server/Ginkgo.Api/Controllers/FilesController.cs`
- Web：`web/src/views/admin/system/Files.vue`
- 资源 URL 解析：`web/src/utils/resourceUrl.ts`

## 8. 注意事项
- 资源文件不应直接散落到业务目录，应通过统一文件表和存储链路访问。
- 批量删除或移动前要确认是否已被系统配置、通知附件或插件引用。

## 9. 常见问题
- 文件上传成功但打不开：先检查文件内容接口、下载接口和资源路径解析。
- 资源 URL 不正确：检查统一 URL 解析逻辑，避免代码里手写拼接。
